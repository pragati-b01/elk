Azure Blob Storage SFTP supports restricting an SFTP local user to a specific directory within a container, so you can keep your existing single-container structure and give each user access only to their assigned folder. Microsoft specifically documents directory-level access using ACLs and SFTP local-user permission scopes. For example, if your container is: mycontainer/ ├── CustomerA/ ├── CustomerB/ ├── CustomerC/ └── CustomerD/ You can configure: userA → only CustomerA userB → only CustomerB userC → only CustomerC Azure Portal steps 1. Sign in to the Azure Portal and open your Storage Account. 2. In the left menu, go to Settings → SFTP. SFTP requires the storage account to have Hierarchical Namespace (HNS) enabled. 3. Make sure SFTP is enabled. 4. Go to Data storage → Containers. 5. Open your existing container. For example: mycontainer 6. Verify that the required folders already exist, for example: mycontainer/ CustomerA/ CustomerB/ CustomerC/ 7. Do not create separate containers. You can continue using the same container because Azure SFTP supports directory-level permissions. 8. Go back to the storage account and select SFTP → Local users. 9. Select Add local user. 10. Enter the username. For example: customerauser 11. Under Authentication methods, select the authentication method you want: SSH password SSH public key or both 12. Find Home directory / Home (landing) directory. Enter the path to the user's folder using: / For example: ```text mycontainer/CustomerA ``` The Azure Portal expects the container and directory path in this format; it is not a folder-selection dropdown. 13. Go to the Permissions section. Select the container: mycontainer 14. Important: Do not give the user broad read/list/write access to the entire container if your objective is folder isolation. Azure's SFTP authorization model allows directory-level access through ACL authorization. 15. Enable ACL authorization for the local user, if the option is available in your portal. 16. Configure the user's permission scope for the required directory. For example, for customerauser: Container: mycontainer Directory: CustomerA Permissions: Read / Write / List / Create / Delete 17. Select only the permissions that the user actually needs. For a user who only needs to download files, use the minimum required permissions rather than giving write/delete access. Save the local user. Repeat the process for the other users. For example: | SFTP User | Home Directory | Access | |---|---|---| | `customerauser` | `mycontainer/CustomerA` | CustomerA only | | `customerbuser` | `mycontainer/CustomerB` | CustomerB only | | `customercuser` | `mycontainer/CustomerC` | CustomerC only | 18. Check the directory ACLs. For SFTP directory-level authorization, the user needs appropriate permissions through the directory hierarchy. In particular, execute (x) permission is required on the container root and directories leading to the user's target directory. 19. Be careful when modifying ACLs. Azure currently has specific SFTP ACL limitations, and Microsoft notes that additional/default ACL entries in the SFTP access path can cause Permission denied errors. 20. Test each account with an SFTP client such as WinSCP or FileZilla. For customerauser, verify that the user can: /CustomerA and can upload/download files there as intended. Then verify that the user cannot access: /CustomerB /CustomerC /CustomerD 21. Also test that the user cannot navigate back to the container root and browse the other folders. Do not give the user container-wide permissions simply to make the SFTP connection work. That is a common configuration mistake because container-level permissions apply to all directories/subdirectories in that container. For granular directory access, use ACL authorization. Recommended configuration For your scenario, I would use this structure: Storage Account └── mycontainer ├── CustomerA ├── CustomerB ├── CustomerC └── CustomerD And configure: SFTP Local User: customerauser Home Directory: mycontainer/CustomerA ACL: CustomerA Permissions: r/w/l/c/d as required 22. The key point is that the Home Directory alone should not be treated as the security boundary. Use the SFTP local-user permission scope/ACL configuration to enforce the directory restriction. Azure documents ACLs specifically as the mechanism for restricting a user's access to a particular directory while preventing access to other directories in the same container.
